# Security Policy

## Supported Versions

NetPulse is currently under active development.

Security updates are only provided for the latest version available on the `main` branch.

| Version         | Supported |
| --------------- | --------- |
| Latest (`main`) | ✅         |
| Older versions  | ❌         |

---

## Reporting a Vulnerability

If you discover a security vulnerability in NetPulse, please report it responsibly.

**Do not open a public GitHub issue for security vulnerabilities.**

Instead, contact:

* Email: [sohamd008@proton.me](mailto:sohamd008@proton.me)

Please include:

* A description of the vulnerability
* Steps to reproduce the issue
* Potential impact
* Screenshots, logs, or proof-of-concept code if available

---

## Response Process

After receiving a report:

1. We will acknowledge receipt as soon as possible.
2. We will investigate and validate the issue.
3. If confirmed, a fix will be developed and released.
4. Public disclosure may occur after a fix is available.

---

## Scope

Examples of vulnerabilities that may be relevant include:

* Cross-Site Scripting (XSS)
* Injection vulnerabilities
* Authentication or authorization flaws
* Sensitive data exposure
* Dependency-related security issues
* Cloudflare Worker or API security issues

---

## Security Best Practices

Users self-hosting or modifying NetPulse should:

* Keep dependencies up to date
* Review third-party integrations
* Configure Cloudflare security features appropriately
* Avoid exposing internal APIs unnecessarily

Thank you for helping improve the security of NetPulse.
